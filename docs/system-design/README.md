# System design

The design of go-slow: how it models the editorial work of a slow-news briefing, and why it has this shape. Terms are defined in [`CONTEXT.md`](../../CONTEXT.md).

## End state

No end state is declared over this design. A hypothesis about the end state is read from what the **Commands** output, so it is declared with the **Commands** whose output it reads, once they have a shape worth testing. Declared over **Commands** still being redrawn, it would be read on an instrument that changes with every redraw: its readings would be deferred each time, and the **Commands** re-recorded for a reading that never comes.

## Shape

The editorial work is the one core domain. Collection and storage are adapters around it (the Web apps Guide's ports and adapters): they fetch and keep material, and make no editorial judgement. The value of the project is the editorial work, so it is the part kept free of I/O and tested directly.

**An agent edits, and the Owner reads.** The **Editor** does the editorial work without waiting on the **Owner**. The **Owner** reads **Stories**, and chooses the **Sources** and **Topics**; what the **Owner** notices about the editorial work changes its design, through issues and design sessions, not through the **Record**. A briefing the **Owner** had to edit would wait on the **Owner**'s time, the opposite of one they read. While the **Commands** are being worked out, judgements the **Owner** gave inside the app would fix the shape of what they judge; what the **Owner** notices changes more when it changes the **Commands** themselves.

**The output is the same for every reader.** There is no model of an audience: no per-reader selection, no segments, no engagement signal. A briefing personalised per reader would multiply the editorial work by the number of readers and turn judgement into ranking. One output keeps the editorial work the thing that is done, once.

**go-slow is private: the Owner is its only reader.** It is not publicly reachable. Publishers' terms and UK copyright law draw their sharpest line between private, personal, non-commercial use and publishing to others, so a private go-slow can use the widest set of **Sources** and keep the most of each. Opening it to other readers changes nothing in the editorial design, since the output is already the same for every reader, but it changes what the **Record** may hold and which **Sources** may be collected, and is made only once licensing allows it.

**go-slow runs when the Owner starts it.** It runs on the **Owner**'s laptop, from the same image and compose file it is developed with, and its port is published on the loopback interface only, so it stays private on any network the laptop joins: a port open on every interface would serve the **Record** to everyone else on a shared network. The **Record** is an ordinary folder on the laptop, mounted into the container, so the **Owner** can see it, copy it and keep it across resets of Docker. Nothing keeps go-slow running when the **Owner** hasn't started it: a host running it unattended would do editorial work nobody reads. While it is stopped nothing is collected, and its first **Collection** run on starting brings in what the **Sources** carry since.

## The Record

**The Record keeps Events; everything else is a Projection.** An **Item** collected and each **Judgement** is kept as an **Event**, at its own grain, with an identifier and the version of its shape, and is never changed. What can be worked out again from the **Events** is a **Projection**: the **Spans** a **Story** holds as at a time, which **Spans** mention an **Entity**, a **Command**'s input, a **Page**. The **Record** as it stood at a time recurs through the design: every **Command** reads it, and a **Projection** chooses whose **Judgements** it reads, and a **Record** that kept only its current state could answer neither. **Sources** and **Topics** are kept as plain records, changed in place: they are configuration the **Owner** sets, not something that happened. Shapes are versioned because **Events** are never rewritten: a **Projection** reads every version of an **Event** it has ever been given, rather than a migration rewriting history into the newest shape.

**A Command reads a Projection and outputs zero or more Judgements; a Projection only reads.** Every piece of the **Editor**'s work is a **Command**, and a **Command** is the only thing that writes a **Judgement**. A **Projection** is plain code: it calls no model and writes nothing, so it can be worked out again at any time, and opening a **Page** changes nothing. A **Command** reads a **Projection** shaped for its work, gets its text through **Spans**, and appends what it judged; it never changes an **Event**. Reading a **Projection** rather than the history keeps each **Command**'s input bounded however long the **Record** grows, and keeps each **Command** self-contained: no **Command** waits for another to have run, or knows which ran before it. So the **Record** is eventually consistent. A **Command** run again over a **Record** that has moved on (a **Span** hydrated since, an **Entity** looked up) can judge differently, and that is intended: it is how judgements improve as the **Record** fills in. Ordering the **Commands** (hydration before any editorial work, say) would make the slowest hold up every one after it.

**The Record is recreated when the design of its Judgements changes, not translated.** When the **Judgements** the **Record** keeps change in kind, those made in the old kinds are left in the **Record** as **Events** no **Projection** reads, and the **Commands** are run again over the **Items**. None is carried into the new kinds, because a translation is a judgement no **Judge** made: a Fact reworded from an **Item** would become an address the words were never judged at, and a relation between two **Spans** turned into a **Story** in code would join every subject a **Span** that says two things touches. What carries through is what happened rather than what was judged: the **Items**, with their text and when they were collected, and the kept calls, which are never removed. Each switch is kept as an **Event**. Running the **Commands** again over the **Items** collected before a switch calls the model over the whole **Record**, so it is a run the **Owner** starts, priced first (*Every Judgement carries its Judge*), never work the next start takes up unasked.

**Text is kept apart from the Events, so it can be forgotten.** An **Item**'s text is stored beside the **Events**, which refer to it by **Item** and address, so a **Source**'s terms that require forgetting an **Item** are met by removing its text, while the **Events** stay append-only and their addresses point into text that is gone. Forgetting has to reach every copy: the kept calls and the recordings hold text too. Every **Source** today is under the Open Government or Open Parliament Licence with full text kept, so nothing is forgotten yet. An address is into the text as kept, the publisher's HTML, not into a plain-text rendering of it, since a rendering is code that can change and would move every address with it; the words at an address are read by dropping its tags. An **Item** collected with only its summary is not cut until its text is fetched, so no **Cut** addresses text that changes after it.

**Every Judgement carries its Judge, and a changed Judge judges forward.** A **Judge** is the **Command**, its instructions' version, the model and the request's hash, as kept calls record. A new version of a **Command** is a new **Judge**: it judges what arrives from then on, and the **Judgements** made before stand, with their **Judge**. A **Projection** reads, for each thing judged, the newest **Judge** that has judged it, so the **Record** mixes **Judges** over time, and every **Page** can say which **Judge** made what it shows. Re-judging the whole **Record** with every change would cost as much as the **Record** is large, growing daily, for every instruction tried; re-judging a range is a deliberate run on the **Owner**'s say, priced first, as a re-recording is. A **Candidate** is compared on the live **Record** by re-judging a sample, kept beside the live **Judgements** and read by no **Projection** until it is chosen; since **Spans** are addresses that never change, no **Judgement** is ever left pointing at nothing by a **Judge** that judged differently. Choosing a **Candidate** is itself an **Event**, and rewrites none of its **Judgements**: from the choice on, the **Candidate** is a live **Judge** whose **Judgements** count as made when it was chosen, so they are newer than every live **Judgement** made before the choice, and a live **Judgement** made after it is newer still. Ordering them by when they were made instead would let a live **Judge** that judged the same thing between the **Candidate**'s run and its choice outrank the **Judge** just chosen. A **Candidate** is chosen only on the model and version the **Command** runs on from then, so the **Judge** the **Owner** chose is the one that goes on judging what arrives. A re-judging run calls the model in real time, one request at a time, though a batch costs half: the run is a one-off the **Owner** starts and watches end, and a batch would either hold it open for up to a day or leave its results to the app's timetable, which applies only work awaiting a **Command**, not work judged again. Its price is estimated before it runs, in dollars at real-time rates, from a price table kept with the model adapter and dated, and the dry run prints the date, so a stale table shows where it is used. Re-judging reads only **Items** cut, so a run first cuts the **Items** in its range that have text and no **Cut**, as **Collection** would (plain code, no model call). Those **Cuts** are the dry run's only write. The run stops before a call that could take it over the most it may spend, since the estimate is only an estimate.

## Construction

**The Span is the unit, and it is an address.** A **Span** is a stretch of an **Item**'s text, known by where it starts and ends, and everything go-slow says about what an **Item** says is a **Judgement** on its **Spans**. A **Span** is never reworded: a proposition reworded from its **Item** stutters against the text it came from, and in doing so it resolves references ("the city" becomes Derby), which is a judgement of its own, invents attributions ("Andy Burnham said:" becomes the subject of every sentence after it), and loses the speaker's voice ("This is fantastic news for Derby", the Mayor's view, restated in go-slow's own). A **Span** keeps all three apart: the words are the publisher's, and what they refer to and who speaks them are **Judgements** on them. Because the text is never rewritten, an address always points at the same words, so no **Judgement** is ever left pointing at something changed. The whole **Item** is not the unit either: an **Item** says several things that belong to different **Stories** (a press release moves devolution on and announces a rail line), and a **Story** of whole **Items** would tie everything in one to everything in the other.

**The grain belongs to the Judgement, not to the Span.** **Spans** nest, from the whole **Item** to a word, and each **Judgement** is about the stretch it needs: *refers to* is about "the city" and "Derby", a **Story** holds the sentences its **Item** was cut into. A **Cut** lists an **Item**'s **Spans** before anything else is judged of them (sentences, today, by plain code), so that each **Judge** is shown the **Item** as numbered **Spans** and cites them by number, which models do reliably, where character offsets they do not; what is stored is the address the number stands for, and a **Judge** can cite a finer stretch as words quoted within a **Span** of the **Cut**. Quoted words stand for their first occurrence in the **Span**, so a *refers to*, whose words recur (two "they"s in one sentence, referring to different things), quotes its stretch and, apart from it, words around it that locate it; only the stretch is kept. A **Judge** that could only quote would reach a second "they" only by quoting the words around it, and the stretch kept would then hold words the **Judgement** is not about ("they then found" refers to Manchester City Council), which hydration replaces with what they refer to. A fixed grain chosen at construction would make every later **Judgement** work at it. The **Cut** is a **Judgement** like the others, kept with its cutter, so a better cutter (one per **Source**, or a model) adds a **Cut** without invalidating any **Judgement** made on an earlier one: a **Judgement** is about an address, whichever **Cut** listed it.

**Construction judges a Span from its Item; editorial work judges Stories.** The **Commands** fall into two kinds by what they read. *Construction* (the **Cut**, hydration, look-ups) judges a **Span** from its own **Item** alone: what it refers to and names, who speaks it, whether it is **Rejected**. It runs as each **Item** arrives, independently of every other. *Editorial work* (**Merge**, **Split**, **Name**) reads **Stories**, each with its **Spans**, and changes or names them. Hydration is construction, though it needs a model, because it reads only the **Item**; and nothing waits for it: a **Span** is in a **Story** once it is cut, and one hydrated later is read hydrated by the next **Command** that reads it.

**Hydrating a Span makes its model Judgements in one call, reading its whole Item.** Shown its **Item** as its **Cut**, *hydrating a Span* judges what the **Span** *refers to*, what it names (a name and its kind), who speaks it, and whether it is **Rejected** as not useful. Each **Judgement** is kept as its own, with the call as its **Judge**, so a **Projection** can take one kind from a newer **Judge** and another from an older one. A **Span**'s four **Judgements** are made together because they depend on each other (the speaker of "This is fantastic news for the city" is the Mayor through "he"; whether a **Span** says anything depends on what it refers to), and judged apart they could contradict each other. The unit is the **Span**, not the **Item**, because the **Span** is the unit of everything else: a **Span** a better cutter lists is hydrated without judging its **Item**'s other **Spans** again, and a **Span** judged again is judged alone. The whole **Item** is shown each time, because what a **Span** refers to and who speaks it are usually in the sentences around it; the **Item** is the same prefix for each of its **Spans**, so a provider's prompt cache carries most of the repetition.

**Entities are looked up by name, not by Span.** What a name refers to in Wikidata is looked up in plain code, keyed on the name and its kind, and for a person named by office on the office and the **Item**'s date, so "Derby" in a hundred **Spans** is one look-up, and a look-up refused or delayed holds up no hydration. A look-up made per **Span** would repeat the same request for every **Item** naming a common **Entity**, at the one request a second Wikidata's rules allow, and one refusal would stop the hydration that made it.

**Entities come from Wikidata first, otherwise from the Editor.** What a **Span** names (a person, organisation, place or named occasion) is looked up in Wikidata, and a match is used as it is. With no match, the **Editor** makes its own **Entity** (a would-be candidate, a councillor, a new campaign group); if Wikidata later gains an item for it, the two are merged and the **Editor**'s **Entity** stays as an alias, so the **Record**'s history still resolves. Wikidata gives identity, so "Andy Burnham", "the Prime Minister" and "Burnham" in three **Items** are one **Entity** without go-slow solving that matching itself. Abstract subjects are **Topics**, not **Entities**.

**The model names what a Span names; plain code finds it in Wikidata.** *Hydrating a Span* gives each name the name the **Item** uses, its kind, and for a person the office the **Item** gives them, in full ("the Prime Minister", office *Prime Minister of the United Kingdom*). Only a person has an office, and code drops one given to any other kind, refusing nothing, since the model fills the field whenever anything nearby describes what an **Entity** does and instructions can't hold it off. Matching is plain code over Wikidata's answers, as at the **Item**'s date, keyed on the name, kind and office (*Entities are looked up by name, not by Span*). A person with an office is sought first among the office's holders on that date (Wikidata's officeholder statements with their start and end): the one holder, when the **Item** names them only by the office, or the holder whose name contains the **Item**'s ("Burnham"). Otherwise the match is the best item Wikidata's own search ranks whose label or an alias is the name, and of the right kind (a person is an instance of *human*, nothing else is). Anything less certain is no match, and the **Editor** makes its own **Entity**. Letting the model say who "the Prime Minister" is would draw identity from its recall, which is untraced and goes stale exactly where news happens (a model trained before 20 July 2026 names the wrong Prime Minister); an office resolved by date against Wikidata is right for an **Item** from any year. Search alone fails the other way: "Burnham" finds villages before people. An **Editor**'s **Entity** is merged into a Wikidata item when a later look-up matches that item under the same name, or the item's label, so the merge needs no sweep of its own. A look-up Wikidata asks to wait for (replication lag, or its search refusing as too busy) is sent again after a backoff, a bounded number of times; one that still fails is tried again later, and holds up no hydration, since the look-up is its own step.

**Who did what is read in the Span, not judged apart from it.** A **Span** mentions an **Entity** when a **Span** inside it names the **Entity** or *refers to* one that does; that says the **Span** names it, not what part it plays. Which named thing did what to whom is read by a **Judge** in the **Span** itself, since roles were among the least reliable judgements the [news content research](../research/92-news-content-modelling.md) found. The **Speaker** is the one such **Judgement** kept, because whose words a **Span** is is often not in the **Span** at all.

## Stories

**A Story is a group of Spans kept in the Record.** The **Spans** a **Story** holds as at a time are a **Projection** of the **Judgements** that change it. Every **Span** is in at least one **Story**, and can be in several. Kept, a **Story** is the same thing to every **Command** and **Page** that reads it, and a **Span** nothing has looked at since its **Cut** is in a **Story** all the same. A **Story** gathered afresh by each reader would hold nothing between two gatherings, so two readings could group one subject differently, and a **Span** read before its neighbours arrived would be in no **Story** at all. A **Story** drifts as **Spans** join it, and that is how it learns: a subject that moves on is the **Story** moving on. What keeps **Stories** sound is not a rule against drift but that the editorial work goes on: **Stories** are merged and split again as the **Record** fills in, by **Commands** that read them whole. A large **Story** and a **Topic** can look alike, and that is fine: a **Topic** is the **Owner**'s terms and selects nothing, a **Story** is the **Editor**'s grouping.

**An Item gives its Spans their first Story.** The **Cut** that lists an **Item**'s **Spans** puts them in one new **Story**, in plain code: an **Item**'s **Spans** mostly belong together, or the **Item** would be incoherent. So every **Span** is in a **Story** from the moment it is cut, at no model call and waiting on nothing. After that the **Item** links nothing: a **Split** separates **Spans** that belong elsewhere, and a **Merge** brings **Stories** together.

**No relations between Spans are judged.** Whether two **Spans** say the same thing, contradict each other, or one moves the other on is not a **Judgement**: that they belong together is a **Story**. Judged pair by pair, each relation would cost a call per pair and leave a chain for **Stories** to drift along, joining two subjects through any **Span** that says two things, until most of the **Record** is one. Order in time comes from publication.

**Stories change by Merge and Split, each judged over Stories read whole.** *Merging* is shown some **Stories**, each with its **Spans**, and judges which are one. *Splitting* is shown one **Story** and judges whether it is several, and which **Spans** go in each. Each is a **Judgement**, with its **Judge**, so a **Story**'s history is the **Merges** and **Splits** that made it, each linked to the call that judged it. A **Span** moves between **Stories** by a **Split** and a **Merge**, not by a judgement of its own: whether one **Span** belongs with a **Story** is the same question as whether a **Story** of it does, and is best judged where both are read whole. The **Owner** changes no **Story** by hand: what the **Owner** notices about how **Stories** are formed changes **Merge** and **Split** themselves.

**Every Story has a Name, and nothing reads it but the Owner.** *Naming a Story* reads its **Spans** and writes a short subject, so the **Owner** has something to recognise it by in a list. The **Name** is go-slow's own words, so no **Command** is shown it: a **Command** reading a **Name** would be judging a rewording, which a **Span** declines (*The Span is the unit*).

## The Editor

**The Editor's work is a set of Commands.** Each is a bounded step with a typed result, reading a **Projection** and writing back only what passes its checks:

- *Construction*: *cutting an Item* lists its **Spans** and puts them in the **Item**'s **Story**, in plain code; *hydrating a Span* judges what it refers to, what it names, who speaks it and whether it is **Rejected**; *looking up a name* finds it in Wikidata, in plain code.
- *Editorial work*: *merging*, *splitting* and *naming* **Stories**.

A **Command** is a model call where judgement is needed and plain code where it is not. A single agent with tools over the **Record**, deciding for itself what to do each day, fails on three counts. When an output is wrong, the **Command** that made it is known, and so what to fix; with one agent, only that the agent got worse. Each **Judgement** is a property of one **Command**'s result (it is about addresses the **Command** was shown) rather than something an agent must remember. And each **Command** can be tested first, on recorded **Items**, by properties such as "a quoted **Span**'s speaker is who the **Item** says spoke it".

**Every Item is cut and hydrated, and Topics select nothing.** Every **Item** collected is cut and its **Spans** hydrated, whatever it is about. A gate on **Topics** would hide exactly what the **Owner** didn't know to follow, and keeping selection out of construction means a **Span** is judged the same way whatever anyone follows, so no **Item** waits on interest that changes. Hydrating everything is cheap enough not to plan around at go-slow's volume. The **Owner** steers instead through the **Sources**: what is shown per **Source** is how many of the **Stories** it contributes to touch a **Topic** and how many don't, and how many of its **Spans** are **Rejected**, and the **Owner** prunes **Sources** on it. A **Span** touches a **Topic** by the **Topic**'s terms, matched as whole words in the text a reader sees, with no model; that counts, and selects nothing. A **Story** a **Source** contributes to is one that holds, as it stands, a **Span** of one of its **Items**, and it touches a **Topic** when one of its **Spans** does. The counts are **Projections** over a stated window, the last four weeks (the **Stories** holding a **Span** of an **Item** collected in it, the **Spans** of those **Items**), worked out on every **Page** and never stored, so taking up or removing a **Topic** changes them at once and changes nothing else. Four weeks is long enough for a **Source** that publishes weekly to show a few **Stories**, and short enough to show a **Source** as it is now rather than as it was. A **Topic** has terms, since terms are the only way a **Span** touches one: a **Topic** given only **Sources** would say where **Items** come from, which the counts already show.

**The model is an adapter, and the one adapter is Claude.** Every **Command** that calls a model does so through a provider-neutral port, and each **Command** owns its instructions and output schema, so the **Commands** are tested against a fake and each **Command**'s model is a configuration value. The one adapter is Claude through Anthropic's API, and which Claude model runs which **Command** is chosen on the recorded fixtures by their properties ([model research](../research/models.md)). Open-weight models are not used. From an inference provider they are paid per token like Claude, so the most they could save is less than a second adapter, a second set of recordings for every **Command** and a measurement between providers cost to build and keep. Where they would be free at the margin, a model the **Owner** runs, they need a machine running all day, and the models such a machine holds are not the frontier ones. The port stays provider-neutral, so a second adapter stays a new integration rather than a redesign, if the cost of the calls ever outgrows the cost of the work. Each **Command** runs on a pinned model ID, one whose weights the provider never changes, so behaviour can't change under a green recording without a change in go-slow; an alias the provider moves to a newer model would change the **Command** while every recording still passed. A model's ID is part of the **Command**'s request, so changing it is a re-record, like changing the **Command**'s instructions. Each result keeps the model the provider reports answering with, not the one asked for, so if a configured ID ever did move, the **Record** would show it.

**A provider never trains on go-slow's requests and keeps them only for a limited, stated period.** Most of what is sent is public, but what go-slow asks about over months (which **Sources**, which **Stories**) is a profile of what the **Owner** follows. Strict zero retention would shut out most closed models' standard terms for little gain over a profile of interests; a provider that trains on requests or keeps them indefinitely is excluded.

**Commands that call a model run in batches.** Nothing waits on a single **Span** or **Story**, so the work is submitted together and processed asynchronously, which is cheaper where a provider discounts batches, as Anthropic does. A batch is never waited on: after each **Collection** run the results of batches that have ended are applied, through each **Command**'s own checks, and then everything awaiting a **Command** and not already in a batch is submitted as one batch. Results are matched to their work by the identifier each request was given, never by position, since a provider returns them in any order. Work stays awaiting its **Command** until its result is written, and the pending batches are kept in the **Record**, so a restart picks them up and a result is applied to the work as it stands when it arrives. A result for work that would now be asked otherwise (its **Projection** has moved since the request was sent) answers a question no longer the work's, so it is refused and the work asked again as it stands. A request that failed, expired or fails its **Command**'s checks is resubmitted alone, so one bad piece of work confines its failure to itself rather than waiting for the next batch or holding one up. Construction runs after each **Collection** run, so the **Record** is current within a run or two of an **Item** arriving.

**Work that keeps failing is given up after three attempts, and taken up again by hand.** Each piece of work (one **Command** on one **Span**, **Item** or **Story**) gets three attempts across its batches, the first and each resubmission alike; after the third failure it is marked failed in the **Record**, with when and why it last failed, and is no longer submitted. A batch that has not ended, or cannot be polled, two days after it was submitted (twice the day within which a provider ends one) is given up, and counts a failed attempt for each piece of work in it, so a batch that disappears at the provider or never ends doesn't leave its work pending for good. A result that came back but fails to be applied for a reason other than the **Command**'s checks (a Wikidata lookup refused, the **Record** failing) is not an attempt: the attempt is the model call, and that call answered. It stops only that result: the batch's other results are applied in the same run, the batch is kept holding only the requests still to apply, so their work is not submitted again, and each run applies them again from the kept results, at no model call, until they apply. The line between waiting and counting is the batch's deadline: a result still failing to apply when its batch is two days old counts a failed attempt, as a lost batch's work does, so a fault that never passes ends in the work being marked failed and listed, not waiting for good. Stopping the whole run at such a result would hold up every result behind it and everything new waiting to be submitted, on every run, for one passing refusal. The cap is there because every attempt is a model call: a request whose answer always fails its checks, or is always refused, would otherwise be paid for on every **Collection** run without bound, and a failure that persists across three attempts, minutes to hours apart, is one in the work or the **Command**, not in the provider, so a fourth attempt is unlikely to fare better. Failed work no longer awaits its **Command**, so nothing waits behind it. Failed work is listed on the **Items** **Page** with its reason rather than dropped silently, since a **Span** never hydrated is a gap in the **Record** the **Owner** should know of. Retrying is by hand, through the `retry` admin command, which clears the failed marks and resets the attempts: what fixes failed work is a change the system can't see (a **Command**'s instructions or checks, a provider's outage, a malformed **Item** corrected at its **Source**), so retrying on a timer would only spend the calls the cap saves, and the **Owner** is the one who knows the cause has been dealt with.

**Every model call is kept, as it was sent and as it came back.** Each call a **Command** makes is kept with the **Command** and the piece of work it was for, the request exactly as sent (instructions, schema, input, the **Projection** it was shown, the model asked for), the response exactly as returned (thinking and refusals included, in the provider's own form, beside the model the provider reports, the usage and why it stopped), and what the **Command**'s checks said of it. A result the checks refused is a kept call like any other, with its reason; a request in a batch that ended without answering it is kept with no response. This is for diagnosis: when an output looks wrong, the **Command** that made it is known, and the kept call says why it judged as it did, from what it was shown rather than from a reconstruction. A mistake can be noticed weeks after the call that made it, so calls are kept for good and never rewritten. Each carries a hash of its request (instructions, schema, input and model), computed as recorded runs compute theirs, so a call in use and a recording share one meaning of "the same request": whether today's code would still send it is a comparison, and a call that went wrong is already a fixture's input, since every **Source** is admissible. The request ties a call to the code that made it better than a commit would: the **Projection** it was shown depends on the **Record** as it stood, and a commit can't say what a build from uncommitted code sent. The kept calls are a side record: no **Command** is shown them, since a **Command** shown its own earlier answers would be taking instructions by another route (the Model calls Guide). Usage is shown as tokens, summed per **Page**, not as money: prices change, and a **Page** priced from a table in the code would go stale unseen. The one place a price is worked out is a re-judging run's estimate (*Every Judgement carries its Judge*), which prints the date of the prices it used.

**The Editor is tested in three tiers.** Unit tests replace the model with a fake, injected rather than patched, and test first everything around the model call: typed results, the checks before writing back, and tracing. Recorded runs call the real model on fixture **Items**, keep its responses, and replay them in the suite, asserting properties (a pronoun *refers to* its antecedent, a quoted **Span**'s speaker is who the **Item** says spoke it, a speech and the press release announcing it end in one **Story**); they are re-recorded deliberately when a **Command**'s instructions change, and the difference shows what changed. A replay is valid only for the request it answered. Each recording keeps that request's hash: its instructions, schema and input (frozen inputs included), and the model the **Command** is pinned to, by the one function a kept call is hashed with. A replay whose **Command** now builds a different request fails as stale, naming the command that re-records it. Without this, a change to a **Command**'s instructions leaves its old recordings green while they test a prompt that no longer exists. It fails rather than skips, because a skipped property quietly tests nothing, and a recording that keeps no hash is stale too. Whether the **Editor** judges well is not a test but a reading, in use, through the end state, once one is declared (*End state*). So the suite never pays for a model call; only a deliberate re-recording does. Fixtures come only from admissible **Sources**, since the suite is committed.

**Each Command is recorded over its own frozen inputs.** Each **Command** is recorded over its own frozen copies of the recordings it rests on (the editorial **Commands** over hydration's), never over the upstream recordings themselves, so re-recording one **Command** leaves every other **Command**'s recordings valid, and a change to a **Command** is re-recorded on that **Command** alone. The copies are earlier **Commands**' recordings, made by the production path, not hand-made **Record** fixtures: hand-made **Judgements** would let an editorial **Command** pass on input no hydration writes. A frozen input is part of the **Command**'s request, so refreshing it makes the **Command**'s recording stale. Refreshing is a change of its own, never part of the change to the **Command** upstream: that **Command**'s new behaviour is accepted on its own recordings first, and then the copies are refreshed and what rests on them re-recorded, once, rather than once per fix. A refresh copies every upstream **Command**'s recordings together, because a downstream **Command** frozen on a mix no run of the **Editor** produces would be tested on that mix. Until a refresh, the **Commands** downstream are tested on what the earlier **Commands** used to write. Each **Command**'s current recordings (each fixture's first sample) are fed to the **Commands** downstream with a fake model, asserting that their requests build and the fake's answers pass their checks, so a change to an earlier **Command**'s output that a later **Command** can no longer take fails at once. A change in what the earlier **Command** judges, rather than in what shape it writes, is not a failure of the code; a refresh is what brings it downstream.

**A recording is one sample, and a property is judged by its pass rate.** A recorded **Command** is stochastic, so one recording passing says only that it passed once: a property passing one try in three passes a single recording a third of the time, and that pass is luck nothing could show. So each fixture is sampled several times when it is recorded, and each property is judged by the rate at which the samples pass it. A sample is one piece of work run as it runs in use, with its attempts against the **Command**'s own checks (`MaxAttempts`), and the two kinds of property are rated apart, because they fail differently. A **Command**'s checks run in use, so a check that refuses a call costs a retry, not a wrong **Record**: the property is that the work passes within its attempts. The properties only the suite asserts run nowhere in use, so each failure is a wrong **Record**: they are rated over the samples that passed their checks, each call counting. Rating both per call would treat a check that costs a retry one time in three like a property that is wrong one time in three. Each property is judged per fixture, not pooled across them, because a property can fail on one **Item** (the speech) while the rate across all of them looks fine. The rule is declared before the samples are drawn: five samples of each fixture, a property supported at five of five, refuted at three or fewer, and undecided at four, which is read again on five fresh samples judged alone, never added to the first five. No source gives these lines; they are coarse on purpose, since five samples cannot tell a rate of 80% from one of 95%. Every sample is committed, and the suite replays them all and judges each property by its rule on every run, so a property's status is derived from the recordings, never stored. A rate written only into a change's description would be a claim nothing checks again, and a later change to how a property is asserted would quietly leave the samples it was rated on. A refuted or undecided property is a failing test: a refuted one until the **Command** is changed, an undecided one until its fresh samples replace the first ones. The samples answer one request, so they share its hash. Where a **Command**'s fixtures build on each other, every sample of a fixture runs over the same **Record**: the one the fixtures before it left, each carried on by its first sample to pass its checks. A sample run over the **Record** its own earlier samples made would send a request of its own, and five such samples would be five readings of one each, not one request's rate. A frozen copy of a **Command**'s recording, for a **Command** downstream, is its first sample, chosen before its results are seen; copies are refreshed only from recordings whose properties are supported, so that sample passed. Recorded properties are not hypotheses of the end state: they say a **Command** behaves on fixtures, not how the **Editor** does in use, and their status is the suite's.

## Pages

**The Owner reads Stories.** The **Stories** **Page** lists **Stories** by when they last changed, newest first, each by its **Name**; a **Story**'s **Page** shows its **Timeline** and the **Merges** and **Splits** that made it; a **Span**'s **Page** shows its **Stories** and its hydration. Each is a **Projection**, worked out when it is opened, so opening one changes nothing and what it shows is always what the **Record** holds then. A daily output written by a model would be a **Command** whose selection is a judgement of its own, made over **Stories** before the **Stories** themselves are sound.

**How each thing was made is one click from it.** Each **Judgement** links to the call that made it (a *refers to*, name or speaker to its **Span**'s hydration, a **Merge**, **Split** or **Name** to its call); each call's **Page** shows its request, its response, what the checks said, and every other attempt at that piece of work. Diagnosis starts from an output that looks wrong, often made by a **Command** upstream of it (a **Merge** made on a wrong *refers to*), so a **Page** per output alone would leave the trail to be rebuilt by clicking back through it.

## How material arrives

**News material arrives only through collection.** Collection checks a fixed set of known sources on its own timetable and lands what it finds in the record. The editorial work runs over that record and fetches no news material of its own. One way in keeps every request to a news source on one timetable, where politeness (request rates, conditional requests, robots.txt) is enforced in one place.

**Collection is polite by these rules.** A publisher's robots.txt is necessary but not sufficient: several allow a generic bot and forbid automated access in their terms, so a **Source** is admitted on its terms, not its robots.txt. **Collection** reads feeds and APIs, not pages. It makes conditional requests where the server supports them and otherwise polls no faster than the feed's own `ttl` or `Cache-Control`. It runs one request at a time per host, backs off the whole host on 429 or 503 for as long as `Retry-After` says, and fetches each robots.txt at most once a day. Each **Source** also has its own rate limit, the least time between two fetches of it, so an API that can't answer conditionally is asked no more often than it changes. Hosts that block scripted clients (Parliament's main site and Hansard) are never fetched, whatever their robots.txt says; their publisher is read only through its APIs. It identifies itself honestly, with a fixed User-Agent naming go-slow and a contact address, and never imitates a browser: a disguised client takes away the publisher's means of addressing it, and some terms treat circumvention as a breach. The findings behind these rules are in [sources research](../research/2-sources.md).

**The record keeps everything collected.** Every item collection brings in stays in the record, including the most that warrant nothing, and the editorial work is layered over it. Whether a detail matters can change: something passed over today is merged into a **Story** a later **Item** starts. With no backfill, an item dropped when it warranted nothing could never be recovered. How much of each **Item** is kept is set per **Source** by its terms, and a publisher becomes a **Source** only if its terms let the **Record** keep what the **Editor** needs: full text under an open licence (GOV.UK and Parliament under the Open Government and Open Parliament Licences), less where the terms allow less (a pollster's results with attribution). **Items** keep the personal data they carry (names in Hansard, in releases, in polls) as published. Having been published elsewhere does not stop a name being personal data; what puts the **Record** outside UK GDPR is that go-slow is private, a purely personal activity (an exemption taken from recall, not yet checked against sources). Opening go-slow to other readers would bring it under UK GDPR as well as the licences.

**An Item is collected with its full text, or not yet.** Where a **Source**'s feed carries only a summary or an opening (GOV.UK's Atom entries, Parliament's written statements list), **Collection** fetches each new entry's full text from the publisher's API (GOV.UK's Content API, the written statement itself), by the same politeness rules, and keeps the **Item** only once it has it. Every **Item** gets its text, because every **Item** is cut and hydrated, and its **Spans** are addresses into that text: an **Item** kept with only its summary would be cut into the publisher's description of it. An entry whose text can't be fetched on this run is left out of it and collected on the next, while it is still in the feed, so an **Item** is always whole and nothing downstream (the **Cut**, hydration, the **Pages**) needs a state for one awaiting its text. *Hydrating a Span* is shown its **Item**'s text without its summary, which stands in only for an **Item** with no text: the summary is the publisher's description of the text, not more of it, and shown beside it, **Judgements** get made on the description (a speech's "delivered a speech in Scotland today") rather than on what the speech says; the **Cut** is of the same text, so no **Span** of an **Item** with text is a stretch of its summary. Collecting the entry at once and completing it later would never miss one, but adds that state and its retries for a case only a long outage at one host makes real: an entry stays in a feed of 50 for a day or more. **Items** collected before their text was fetched are given it once, by the `backfill` admin command, only while they are uncut: every **Judgement** is about an address a **Cut** listed, so nothing has been judged of an uncut **Item**, and giving it its text leaves no **Judgement** pointing at an address that moved. An **Item** already cut keeps the text it was cut from, since its **Judgements** are addresses into it.

**Sources are primary-led.** The **Sources** are primary publishers (government departments, Parliament, statistics bodies, pollsters, parties' own releases) and any reporting outlet whose terms permit storing and summarising its **Items**. Outlets whose terms forbid that are not collected at all: no **Items**, no headlines, no links. The major UK outlets forbid it: the BBC names summaries for one's own use and agentic AI, the Guardian bans automated reading and any AI use, and Reuters requires written consent. Being private does not change this, because UK law permits the temporary copies made while reading but not the stored copies the **Record** keeps. Keeping headline-and-link pointers to those outlets would still take the metadata the BBC's terms forbid taking. The cost is the stories that exist only as reporting, such as an undercover investigation: they reach go-slow through their consequences (resignations, statements, notices), not through the reporting itself. The text of a speech, a statutory instrument or a poll's tables outranks reports of them, and because **Collection** never searches, a primary document is in the **Record** only if its publisher is a **Source**.

**The owner chooses the sources; topics don't.** The known sources are a list the owner maintains by hand. Topics of interest act only in what is counted per **Source**. Following a new topic may lead the owner to add a source, but nothing derives sources from topics: doing so would need source discovery from a topic, which is topic search under another name, and would let the list grow beyond what can be visited politely.

**Releases are collected; series are consulted.** A statistics body or central bank publishes two different things. A release (the ONS's GDP bulletin, an OBR forecast, the MPC's statement) is published on a date, says something and makes news: it is an **Item**, collected on the timetable, and the bodies' release calendars are **Sources** of scheduled releases. A calendar entry is kept as an **Item** with the date it is due and is upcoming until then, so the **Editor** can see a release coming before it says anything; the release itself arrives later as its own **Item**. An entry moved to another date is a new **Item**, since the **Record** is never rewritten, and only its latest date is upcoming. A series (GDP by quarter, the 10-year gilt yield, sterling against the dollar) is background: it is a **Reference source**, looked up when a release makes it matter. A daily yield is not news, and collecting series would fill the **Record** with numbers that warrant nothing. It also keeps market data within what is openly licensed (official yield curves, reference exchange rates, policy rates), since commercial market data is licensed and not to be stored.

**Reference sources are consulted, not collected.** Wikidata, historic datasets (past polls, election results) and statistical series hold background facts about the world rather than news. The editorial work looks things up in them when it needs that background, as hydration's names are looked up in Wikidata.

**The record starts empty and is never backfilled.** Collection's first run sees only what the known sources carry that day, and the record deepens week by week: an investigation from last year is not in the record until something brings it back. Backfilling from the sources' archives would close that gap, but it is a heavy one-off visit to every outlet, the kind of fetch politeness rules out, and it would leave months of material with no editorial work done on it. The gap closes on its own as the record grows.
